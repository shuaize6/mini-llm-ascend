# M1 预热后短请求性能

2026-10-31，Ascend 310B4、Qwen3-0.6B、FP16、eager、单请求、greedy、关闭 thinking。输入 21 token，固定输出 8 token；源码提交 `ef3dad3`。模型和输入沿用 M0 条件，实际输入/输出 IDs 已与 M0 归档报告逐项核对一致。

本次只新增一次预热和三次测量，没有重跑完整正确性测试集或逐层对拍。运行前没有观察到其他模型进程；编译并行度保持为 2。

| --- | ---: | ---: | ---: | ---: |
| M1 第 1 次 | 151.25 | 134.93 | 7.299 | 1.0961 |
| M1 第 2 次 | 134.26 | 133.01 | 7.508 | 1.0656 |

M1 本次吞吐在 7.30～7.51 token/s 之间，比历史 M0 均值高约 13.5%。**M0 没有在本轮重跑，这不是同一时段的交替对照，不能据此宣称普遍或稳定的 13.5% 加速。** 样本规模也不足以推断 P99、长上下文或高并发性能。

预热是一次完整的同长度请求，耗时 69.25 秒，含编译等待，单独保存在 `warmup_runs` 中。它不参与上述均值。此前单次启动测得的 0.0375 token/s 继续保留为历史记录，不能当作预热后的速度。

## 计时和内存口径

TTFT 从生成开始到 host 收到首个 token；TPOT 是相邻输出 token 间隔的均值；吞吐为实际输出 token 数除以整次生成耗时。设备在开始和结束处同步。模型加载、分词、输入传输、连续 KV 容量分配、文本解码均不计入生成时间。

每次请求重置逻辑缓存，不复用上次 prompt 的计算。M1 使用预分配连续缓存，容量存储跨请求复用；M0 的 HF 动态 KV 则在生成过程中管理分配，这也是两条实现路径的差异，不能把全部时间差归因于某一个算子。

| 内存项目 | M1 本轮 | M0 历史记录 |
| --- | ---: | ---: |
| NPU allocator 峰值 allocated | 1,301,933,568 B，约 1.21 GiB | 1,200,909,312 B，约 1.12 GiB |
| 测量后的 reserved | 1,321,205,760 B | 1,308,622,848 B |
| M1 连续 KV 容量 | 512 槽，56 MiB | HF 动态缓存，不采用此固定池 |

M1 的 peak allocated 在预热后重置一次，再覆盖三次正式测量。allocator 指标不是整机共享内存使用量，也不包含全部主机/编译进程内存。本轮 M1 总分配峰值高于历史 HF，不能声称已经实现内存节省。

## 分页缓存能否改善速度和内存

**M2 分页缓存尚未实现，因此目前没有分页方案的实测收益。** 分页设计主要用于减少按请求预留和碎片浪费、复用空闲块，进而容纳更多并发请求；相关机制见 [PagedAttention 论文](https://arxiv.org/abs/2309.06180)。

下面只按当前模型的 112 KiB/token 计算逻辑 KV，占用不含权重、临时张量或分页元数据：

| 同一短请求的逻辑容量 | 计算 | 大小 |
| --- | --- | ---: |
| 当前 M1 固定预留 | 512 × 112 KiB | 56 MiB |
| 本次实际 KV 高水位 | (21 + 8 − 1) × 112 KiB | 3.0625 MiB |
| 若 M2 使用 block_size=16 按需分块 | ceil(28/16) × 16 × 112 KiB | 3.5 MiB |

最后一个生成 token 未再次输入模型，所以缓存高水位为 28，而不是 29。分页后的 3.5 MiB 是**本请求会占用的块容量估算**，不是已测出的 NPU 总内存，也不意味着进程实际预留会从 56 MiB 下降到 3.5 MiB。若 M2 仍预分配全局池，收益表现为其余块可以供其他请求使用。

仅把连续存储改成分页存储，不保证单请求 token/s 上升。计划中的 gather + dense 参考路径还会增加索引和临时拷贝，可能更慢。M2 应在相同内存预算和负载下，分别记录活跃块、空闲块、尾块浪费、临时内存和吞吐，再判断实际收益；本轮不提前扩展这些实验。

## 复现命令

```bash
cd /root/mini-llm-ascend
source /usr/local/Ascend/ascend-toolkit/set_env.sh
source .venv/bin/activate
export MAX_COMPILE_CORE_NUMBER=2
export TE_PARALLEL_COMPILER=2
set -o pipefail
python -u -m bench.m1 \
  --model ./models/Qwen3-0.6B --device npu --dtype float16 \
  --max-new-tokens 8 --capacity 512 --fixed-length \
  --warmup 1 --runs 3 --output results/m1-warm.json \
  2>&1 | tee results/m1-warm-output.txt
```
