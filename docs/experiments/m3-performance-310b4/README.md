# M3 编译缓存与性能对照

日期：2026-11-05。缓存探针提交 `b998d8f`，性能脚本提交 `c8eddf9`。沿用 Ascend 310B4、Qwen3-0.6B、FP16。

## 跨进程缓存探针

在一个初始为空的专用目录启用 `ACL_OP_COMPILER_CACHE_MODE=enable`，显式设置缓存路径；两个独立 Python 进程执行相同的 `[1,17,128] × [1,128,19]` MatMul，输入全为 1，输出全部为 128，均通过检查。

| 进程 | PID | 第一次 MatMul（秒） | 同进程第二次（秒） | 执行前/后缓存文件数 |
| --- | ---: | ---: | ---: | --- |
| 第一进程 | 37019 | 5.286516 | 0.000470 | 0 / 10 |
| 第二进程 | 37017 | 0.281801 | 0.000473 | 10 / 10 |

第二进程没有新增缓存文件，所有已有文件内容 SHA256 一致；部分 `.o/.json` 的修改时间被更新，所以不能要求复用时修改时间保持不变。首次 MatMul 约快 18.8 倍，但仍包含运行时加载等开销，并非纯 kernel 执行时间。定时不含 Python 启动、导入、创建输入和输出校验。

证据：[第一进程](cache-process-1.json)、[第二进程](cache-process-2.json)。这支持固定算子跨进程复用磁盘缓存，不代表全部模型形状的缓存命中率。本轮没有重启完整模型两次来测启动加速，避免再增加一次耗时运行。

## 性能协议

两个相同的 21-token prompt 同时到达，各固定生成 8 token，greedy，关闭 thinking。串行控制组使用 M3 Scheduler，max_batch_size=1；批处理组为 2，均复用同一个 32×16 槽（56 MiB）的分页池和一份权重。各预热 2 轮，再按 AB、BA、AB 顺序正式测量 3 轮；每轮共输出 16 token，预热完全排除在摘要之外。

总吞吐为 16 / 完成这两个请求的秒数。TTFT 从共同到达时刻计起，含 submit 和排队；TPOT 是本请求后续 7 个 host token 间隔的平均值。时间戳在 step 返回时采集，同批 token 共享时间戳；包含该步采样及回收，不代表网络流式延迟。加载、分词、池创建和写报告不计时。

新脚本先做一次 CPU 小模型检查，验证样本累计、输出一致性、计时算术和实际批次成员；未重跑既有功能测试套件。然后仅启动这一轮模型性能实验，显式启用固定磁盘缓存 `results/operator-cache`。相同 prompt 是有限负载，不能推广到不同长度、不同到达率或所有并发场景。

## 性能结果

**本轮双请求批处理总吞吐平均 10.744 token/s，串行控制组 6.855 token/s，提升 56.74%。** 这是每组 3 轮的小规模结果；控制组也是 M3 分页调度器，不能将提升比例写成相对历史 M1/M2 的收益。

| 模式 | 每轮请求数 | 平均总吞吐（token/s） | 吞吐范围 | 总 token / 总秒数 |
| --- | ---: | ---: | --- | ---: |
| M3 串行，批次 1 | 2 | 6.855 | 6.800～6.929 | 6.854 |
| M3 合批，批次 2 | 2 | 10.744 | 10.595～10.947 | 10.742 |

逐请求延迟均值：

| 模式 / 请求 | TTFT（ms，含排队） | TPOT（ms/token） | 完成延迟（ms） |
| --- | ---: | ---: | ---: |
| 串行 A | 151.09 | 146.90 | 1179.36 |
| 串行 B | 1331.43 | 143.24 | 2334.13 |
| 合批 A | 203.74 | 183.64 | 1489.25 |
| 合批 B | 203.74 | 183.64 | 1489.25 |

合批提高了系统总输出量，也消除了 B 等待 A 完成的串行排队；代价是 A 首 token 和每个请求的后续 token 间隔变长。合批 A/B 的时间完全相同是 step 返回观测口径的结果，不能据此宣称网络会同时交付每个 token。

预热未混入上述统计：串行两轮耗时 922.115 s、2.322 s，合批两轮为 374.652 s、1.480 s。第一次包含首次形状编译；两个模式并非独立冷进程，后运行的合批可以利用公共算子，不能据此比较独立冷启动速度。完整模型启用固定缓存后仍有新形状首次编译，本轮没有测量第二次完整模型进程的启动时间。

两种模式全部 20 个请求（含预热）的输出均与首轮串行参考一致；每轮请求结束后 allocated_blocks、request_handles 均归零。未重跑 M0～M3 全套测试。
