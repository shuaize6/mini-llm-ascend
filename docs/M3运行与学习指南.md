# M3 运行与学习指南

## 进入与退出

在开发板 Bash 中执行：

```bash
cd /root/mini-llm-ascend
source /usr/local/Ascend/ascend-toolkit/set_env.sh
source .venv/bin/activate
export MAX_COMPILE_CORE_NUMBER=2
export TE_PARALLEL_COMPILER=2
```

CPU 定向验证（不加载真实模型）：

```bash
python -m unittest discover -s tests -p test_scheduler.py -v
```

预期 6 项通过。板端必要短验收：

```bash
set -o pipefail
python -u -m bench.m3 --model ./models/Qwen3-0.6B --device npu --dtype float16 \
  --output results/m3.json 2>&1 | tee results/m3-output.txt
echo $?
```

首次新形状编译可能较久。只运行这一项 NPU 任务，等待退出再启动其他任务。退出码应为 0，JSON 的 passed 为 true。此命令使用 tokenizer 输出的 1/2-token 前缀和 1～3-token 输出验证短批次，不代表完整对话质量或长上下文正确性，也不报告 token/s。

结束后退出虚拟环境与远程终端：

```bash
deactivate
exit
```

## 代码阅读与使用

先读 [设计与原理](M3代码设计与原理.md)，然后依次阅读 `engine/batch_runner.py`、`engine/scheduler.py`、`tests/test_scheduler.py`。核心调用示例（model、ids 已准备好）：

```python
from mini_llm_ascend.cache.paged_kv import PagedKVPool
from mini_llm_ascend.engine.scheduler import Scheduler

pool = PagedKVPool.for_model(model, num_blocks=32, block_size=16)
scheduler = Scheduler(model, pool, max_batch_size=2)
try:
    scheduler.submit("a", ids, max_new_tokens=8, eos_token_id=eos)
    for event in scheduler.step():
        print(event.request_id, event.token_id)
    scheduler.submit("b", ids, max_new_tokens=4, eos_token_id=eos)
    while scheduler.has_pending:
        for event in scheduler.step():
            print(event.request_id, event.token_id, event.finish_reason)
finally:
    scheduler.close()
```

在两次 step 之间可调用 `cancel("a")`。submit 返回请求对象，结束后从 output_ids 读取生成结果。finished/cancelled/failed 都是终态，请求 ID 不可复用。单线程调用，不能在不同线程同时 submit/step/cancel。当前为教学内存内 API，历史请求保留在 requests 中；长期服务需要增加结果清理和队列容量限制。

容量信用不等于已占用块：池实际按需领取块，但准入按最大长度保守估计。等待属于正常背压；过大的单请求会直接报错。失败会释放活跃批次，排队请求可继续 step；close 是最终兜底清理。
